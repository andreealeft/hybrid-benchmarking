Resource estimates

    Resource estimates, fault-tolerant regime

    What a quantum computer could ideally do, before there is one.

    This gives you a lower bound on the cost of running a few quantum algorithms on a problem like yours: specifically, the ones that promise better asymptotic scaling than the classical methods they replace.

    Nothing here is simulated, and no quantum hardware is involved. The numbers come from the published algorithmic analyses, beyond complexity theory, so with prefactors, evaluated for actual problem sizes.

    Counted in three things

    Gates

    Sum up all 1-qubit, 2-qubit and Toffoli gates in the circuit.

    Cycles

    Number of layers of gates, assuming gates in the same layer can run in parallel.

    Queries

    How often the algorithm has to ask for information from the input.

    Which gates? The model: single-qubit gates, two-qubit controlled rotations and Toffoli each count as one. Cycles use the same model, with gates on disjoint qubits sharing a cycle and multi-controlled gates sharing one ancilla register.

    This is not a Clifford+T count. A Toffoli is one gate here, where a fault-tolerant implementation of it costs several T gates and the magic states behind them. So these are logical operations, without error correction assumed: its cost would add on top of every result you see here.

    Two ways in

    Describe your problem in simple numbers

    How many employees, how many delivery stops, how much room in the van. Those answers are mapped onto a model instance of that shape, the classical algorithm is run on it here, and every method is costed on the same instance.

    Good for a sense of the magnitude, and for seeing which method the size of your problem favours. It is a problem like yours.

    the real thing

    Use a data file of your own

    For now this is restricted to certain formats. For an advanced user, going directly through the code is the better route if anything in this interface gets in the way.

    The counts actually depend on the structure of the problem: how ill-conditioned the matrix is, how many columns improve at each step, how deep the layers go, and so on. So the file is read, and the classical algorithm runs here with the analytical resource estimates built in.

    Where this comes from

    Everything here is reimplemented from the published statements: the lemma, not somebody's code. The original repositories are used to check the results against, never copied from. These are the works that were read.

    The studies this puts in one place

    • Hybrid benchmarking of quantum algorithms PhD thesis, Gottfried Wilhelm Leibniz Universität Hannover, 2026. The three case studies below are its three chapters: a gate count, a query count and a cycle count.
    • Realistic runtime analysis for quantum simplex computation arXiv:2311.09995, 2023. The gate count for the quantum simplex, and the instrumented GLPK behind it.
    • Beyond asymptotic scaling: comparing functional quantum linear solvers IEEE Transactions on Quantum Engineering, 2026; arXiv:2503.21420. The query counts for HHL, the Fourier and Chebyshev approaches and the singular value transform, compared on the same instances.
    • A quantum algorithm for solving 0-1 Knapsack problems npj Quantum Information 11, 146, 2025. Where the quantum tree generator based search comes from, and the cycle count built on it.
    • A quantum search method for quadratic and multidimensional knapsack problems IEEE Quantum Computing and Engineering (QCE) 2025, pages 2209–2215; arXiv:2503.22325. The tree generator extended to pair bonuses and to several limits at once.
    • Use case study: benchmarking quantum breadth-first search for maximum flow problems arXiv:2604.24962, 2026.
    • Practical lower bounds for hybrid quantum interior point methods in linear programming arXiv:2604.24362.

    The quantum results they are built on

    • Fast quantum subroutines for the simplex method Operations Research, 2022. The pricing, ratio-test and optimality subroutines costed throughout.
    • Tight bounds on quantum searching Fortschritte der Physik 46, 493, 1998. The schedule behind every search here.
    • Quantum amplitude amplification and estimation Contemporary Mathematics 305, 53, 2002.
    • Quantum algorithm for linear systems of equations Physical Review Letters 103, 150502, 2009.
    • Quantum algorithm for systems of linear equations with exponentially improved dependence on precision SIAM Journal on Computing 46(6), 2017. The Fourier and Chebyshev solvers.
    • Quantum singular value transformation and beyond STOC 2019.
    • Hamiltonian simulation by qubitization Quantum 3, 163, 2019.
    • Exponential improvement in precision for simulating sparse Hamiltonians STOC 2014. The fractional-query reduction the simplex route uses.
    • Quantifying Grover speed-ups beyond asymptotic analysis Quantum 7, 1133, 2023, with QUBRABENCH. The instrumented-classical tradition this extends.
    • A shortcut to an optimal quantum linear system solver arXiv:2305.11352.

    The classical side, which is what actually runs here

    • Maximum flow by blocking flows Dinic's algorithm, instrumented here to log the layer sizes the quantum version's cost depends on.
    • The simplex method Revised, with steepest-edge pricing and Bland's rule as the anti-cycling fallback.
    • Instance formats and benchmark sets DIMACS for graphs and flow networks; the Pisinger and Martello–Toth layouts for knapsacks; Billionnet–Soutif for the quadratic set; OR-Library for the multidimensional one; Matrix Market for linear systems; MPS for linear programmes.

    Every number that comes out carries where it came from: which lemma, what it assumes, the regime it was derived in, and whether it is a bound or exact. A plausible number without that is the thing this tool exists to prevent. Nothing leaves this machine: the page loads nothing from the internet, and no file you point it at is uploaded anywhere.
